# CNV FBC Version Structure

This skill guides agents on how to create, validate, and align the directory and file system hierarchy for any OpenShift Virtualization (CNV) File-Based Catalog (FBC) version in this repository.

## Overview & Architecture

In `cnv-fbc-payloads-new`, each supported OpenShift version is stored as a top-level directory named `v<major>-<minor>` (e.g., `v4-22`, `v5-0`, `v5-1`, `v5-2`).

Kargo pipelines, automated Tekton release pipelines, and CI jobs promote freight payloads between channels and stages by reading from and writing to `payload.yaml` files inside specific sub-folders. **If any required stage folder is missing, Kargo promotions or automated release plans fail.**

## Canonical Reference Layout (`v4-22`)

Every standard version (`v<major>-<minor>`) must contain exactly **17 leaf folders** across four lanes (`candidate`, `nightly`, `stable`, `test`):

```text
v<major>-<minor>/
└── lanes/
    ├── candidate/
    │   ├── errata/
    │   │   └── .gitkeep
    │   ├── gating/
    │   │   ├── .gitkeep
    │   │   └── payload.yaml
    │   ├── konflux-release/
    │   │   ├── .gitkeep
    │   │   └── payload.yaml
    │   ├── prod/
    │   │   ├── .gitkeep
    │   │   └── payload.yaml
    │   ├── release-candidate/
    │   │   ├── .gitkeep
    │   │   └── payload.yaml
    │   ├── stage/
    │   │   ├── .gitkeep
    │   │   └── payload.yaml
    │   └── verify-production-release/
    │       ├── .gitkeep
    │       └── payload.yaml
    ├── nightly/
    │   ├── prod/
    │   │   ├── .gitkeep
    │   │   └── payload.yaml
    │   ├── release/
    │   │   └── .gitkeep
    │   ├── smoke/
    │   │   ├── .gitkeep
    │   │   ├── payload.yaml
    │   │   └── (smokeResults.yaml - auto-generated by CI)
    │   ├── stage/
    │   │   ├── .gitkeep
    │   │   └── payload.yaml
    │   └── verify-production-release/

    │   │   ├── .gitkeep
    │   │   └── payload.yaml
    │   └── verify-production-release/
    │       ├── .gitkeep
    │       └── payload.yaml
    └── test/
        └── verify-production-release/
            └── .gitkeep
```

## File Rules and Invariants

### 1. Mandatory `.gitkeep` (All 17 leaf folders)
- **Every leaf folder MUST contain a `.gitkeep` file (0 bytes).**
- Git does not track empty directories. During promotion lifecycle changes or branch merges, payloads can be modified or removed. Having `.gitkeep` in all 17 leaf folders guarantees that git preserves the directory structure.

### 2. Mandatory `payload.yaml` (13 leaf folders)
The following 13 leaf folders require a `payload.yaml`:
- **`candidate` lane (6 folders)**: `gating`, `konflux-release`, `prod`, `release-candidate`, `stage`, `verify-production-release`
- **`nightly` lane (3 folders)**: `prod`, `smoke`, `stage`
- **`stable` lane (4 folders)**: `prod`, `qe`, `stage`, `verify-production-release`

#### Initialization Rule:
- When creating a new version or adding a lane/stage that has not yet received a promotion, initialize `payload.yaml` with a single comment character and newline:
  ```yaml
  #
  ```
- **NEVER** overwrite existing `payload.yaml` content if the stage already has an active payload.
- This placeholder `#\n` satisfies `yamllint` strict validation (`.github/workflows/yamllint.yml`) while marking the payload as unreleased until Kargo or Tekton overwrites it.

### 3. Folders Without `payload.yaml` (4 leaf folders)
The following 4 folders contain **only `.gitkeep`** and do NOT get a placeholder `payload.yaml`:
- `lanes/candidate/errata/`
- `lanes/nightly/release/`
- `lanes/nightly/verify-production-release/`
- `lanes/test/verify-production-release/`

### 4. Dynamic CI Artifacts
- `lanes/nightly/smoke/smokeResults.yaml` is written and updated by automated smoke test CI jobs. Do not remove or overwrite it when aligning folder structures.

## Scaffolding a New Version or Aligning Existing Versions

### Method A: Using the Bundled Script (Recommended)

The skill includes a dedicated utility script:
`.cursor/skills/fbc-version-structure/scripts/align_version.py`

#### 1. Validate version alignment:
```bash
python3 .cursor/skills/fbc-version-structure/scripts/align_version.py --verify v5-0 v5-1 v5-2
```

#### 2. Scaffold a brand-new version (e.g., `v5-3`):
```bash
python3 .cursor/skills/fbc-version-structure/scripts/align_version.py --scaffold v5-3
```

#### 3. Preview scaffolding without writing files:
```bash
python3 .cursor/skills/fbc-version-structure/scripts/align_version.py --scaffold v5-3 --dry-run
```

#### 4. Align all active versions in the repository:
```bash
python3 .cursor/skills/fbc-version-structure/scripts/align_version.py --align-all
```

### Method B: Manual / Python One-Liner

When authoring or repairing directories without the script:

```python
import os

CANONICAL_LEAF_DIRS = {
    "lanes/candidate/errata": False,
    "lanes/candidate/gating": True,
    "lanes/candidate/konflux-release": True,
    "lanes/candidate/prod": True,
    "lanes/candidate/release-candidate": True,
    "lanes/candidate/stage": True,
    "lanes/candidate/verify-production-release": True,
    "lanes/nightly/prod": True,
    "lanes/nightly/release": False,
    "lanes/nightly/smoke": True,
    "lanes/nightly/stage": True,
    "lanes/nightly/verify-production-release": False,
    "lanes/stable/prod": True,
    "lanes/stable/qe": True,
    "lanes/stable/stage": True,
    "lanes/stable/verify-production-release": True,
    "lanes/test/verify-production-release": False,
}

version = "v5-3"
for rel_dir, needs_payload in CANONICAL_LEAF_DIRS.items():
    dir_path = os.path.join(version, rel_dir)
    os.makedirs(dir_path, exist_ok=True)
    gitkeep = os.path.join(dir_path, ".gitkeep")
    if not os.path.exists(gitkeep):
        open(gitkeep, "w").close()
    if needs_payload:
        payload = os.path.join(dir_path, "payload.yaml")
        if not os.path.exists(payload):
            with open(payload, "w") as f:
                f.write("#\n")
```

## Post-Creation Verification Checklist

Before opening a pull request or committing changes:

1. **Verify folder count**:
   ```bash
   find <version>/lanes -type d -links 2 | wc -l
   # Expected: exactly 17 leaf directories
   ```

2. **Verify `.gitkeep` presence**:
   ```bash
   find <version>/lanes -name ".gitkeep" | wc -l
   # Expected: exactly 17 .gitkeep files
   ```

3. **Verify `payload.yaml` count**:
   ```bash
   find <version>/lanes -name "payload.yaml" | wc -l
   # Expected: exactly 13 payload.yaml files
   ```

4. **Verify YAML syntax**:
   Ensure all `payload.yaml` files have valid syntax (`#\n` or standard FBC dictionary).
